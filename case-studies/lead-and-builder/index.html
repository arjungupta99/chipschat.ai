Case study: a frontier lead and an open-source builder

The same four jobs went to Claude Code on its own, and to Claude Code leading an OpenCode agent on a free open model. This is what each setup cost and how long it took.

The setup

Each job went to two new spaces in Chips, with the same message in each.

  • Claude Code alone did the whole job itself.
  • Claude Code as the lead planned the job, handed the building to an OpenCode agent with an @, and checked the work before saying it was done.

Claude Code ran Opus 5.5, at high effort on two jobs and medium on two. The OpenCode agent ran DeepSeek V4.1 Flash Free, which costs nothing on OpenCode.

What the case study found

The lead's cost hardly changed with the job. At medium effort, planning and checking cost Claude Code 35 cents for one page and 31 cents for an app three times its size. Working alone, its cost grew with the job.

So the bigger the job, the more you save. On the small page at high effort, checking the work cost as much as building it, and the split saved nothing.

It takes longer. The open-source builder took two to four times as long as Claude Code working alone.

A second pair of eyes helps, up to a point. The leads caught real bugs, six of them in the recipe box's quantity maths, and sent them back to be fixed. On the expenses app, the review missed a case where the settle-up list used one more payment than it needed to. Claude Code alone got that one right.

Effort matters as much as the split. At medium effort the same page cost 42% less with a lead and 27% less alone, and still passed every check.

Once, the builder stopped partway. Its model ran out of room while thinking, and the lead noticed and sent it back to work. Chips now tells a model that gets cut off to carry on by itself.

How it was measured

  • Each cost is what Claude Code reported to Chips, checked against its requests' tokens at Anthropic's published Opus 5.5 prices. Thinking counts as output, so the effort level is in the cost.
  • Working time runs from the message to "it's done", and leaves out time spent waiting for a person to approve a command.
  • Every page and app was checked with the same cases: the same test bill, the same shopping lists, the same splits.
  • Each job ran once, so treat these numbers as a sample, not a benchmark.
